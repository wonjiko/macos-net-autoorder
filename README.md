# net-autoorder

macOS 네트워크 서비스 순서를 회선 품질에 따라 5분마다 다시 매긴다. 유선이 연결된 채로 품질만 나빠졌을 때 Wi-Fi 같은 다른 회선으로 넘어가게 한다.

macOS는 링크가 끊기거나, IP를 못 받거나, 라우터가 ARP에 응답하지 않을 때만 서비스 순위를 내린다. 패킷 손실과 지연은 보지 않으므로 케이블이 꽂혀 있는 한 나빠진 유선을 계속 쓴다.

## 동작 규칙

- IPv4 주소가 있는 서비스 전부에 `1.1.1.1`로 ping 30회를 동시에 보낸다.
- 손실률이 낮은 순, 손실률이 비슷하면 RTT가 낮은 순으로 줄을 세운다.
- 두 서비스의 손실률 차이가 5%p 미만이면 RTT가 상대의 70% 미만일 때만 앞세운다. 그 밖에는 현재 순서를 유지한다.
- 1순위의 손실률이 20% 미만이고 30초 동안 트래픽이 100KB/s를 넘으면 그 주기는 순서를 유지한다.
- 1순위의 손실률이 20% 이상이면 트래픽과 관계없이 순서를 바꾼다.
- 응답이 없거나 주소가 없는 서비스는 서로의 순서를 유지한 채 뒤로 간다.

## 판단 근거

- 대역폭 대신 손실률과 RTT로 회선을 비교한다. 대역폭을 재려면 인터페이스마다 파일을 내려받아야 해서 트래픽이 크고, 테더링 인터페이스에서는 데이터 요금이 나간다.
- ping은 `ping -b <인터페이스>`로 인터페이스에 고정해 보낸다. 기본 경로로 보내면 VPN이 기본 경로를 잡고 있을 때 VPN 상태가 섞이고, 1순위가 아닌 회선은 잴 수 없다.
- 순서를 바꾸면 기본 경로가 다른 인터페이스로 옮겨가 SSH, 화상회의, VPN 같은 기존 연결이 끊긴다. RTT 차이 70% 기준과 트래픽 보류 규칙은 이 끊김을 줄이려는 장치다. 평소 유선과 Wi-Fi는 RTT가 몇 ms 차이라 RTT만으로 정렬하면 5분마다 순서가 뒤집힌다.
- 트래픽 보류에 손실률 20% 조건을 붙인다. 나빠진 회선도 재전송 때문에 트래픽은 계속 흐르므로, 트래픽만 보고 보류하면 나빠진 유선에서 영영 넘어가지 못한다.
- 트래픽은 1순위 인터페이스의 `netstat -ib` 바이트 카운터가 ping 30초 동안 늘어난 양으로 잰다. 받은 양과 보낸 양을 합쳐 업로드 위주 사용도 잡는다.

## 설치

```sh
git clone git@github.com:wonjiko/net-autoorder.git
cd net-autoorder
sudo ./install.sh
```

- 서비스 순서 변경에 관리자 권한이 필요해서 root LaunchDaemon `local.net-autoorder`로 돈다.
- launchd는 `~/Desktop`, `~/Documents`, `~/Downloads` 아래 파일을 읽지 못한다. 그래서 설치할 때 스크립트를 `/usr/local/libexec/net-autoorder.sh`로 복사한다. 저장소의 스크립트를 고친 뒤에는 `sudo ./install.sh`를 다시 실행해야 반영된다.

제거는 `sudo ./install.sh uninstall`이다. 로그 파일은 남긴다.

## 확인

```sh
./net-autoorder.sh --dry-run    # 측정하고 계산한 순서만 출력한다. 30초 걸린다
./net-autoorder.sh --selftest   # 가짜 측정값으로 정렬 규칙과 보류 규칙을 검사한다
tail -f /var/log/net-autoorder.log
```

로그는 실행마다 한 줄이다. `keep`은 순서 유지, `apply`는 변경이고 뒤에 새 순서가 붙는다.

```
2026-10-14 11:31:59 keep  rate=311173B/s [USB 10/100/1000 LAN 0.0% 2.935ms] [Wi-Fi 0.0% 9.049ms]
```

## 한계

- 측정 대상이 `1.1.1.1` 하나다. 이 주소를 막는 네트워크에서는 모든 서비스가 손실 100%로 나와 순서를 바꾸지 않는다.
- 휴대폰 테더링도 후보에 들어간다. 유선과 Wi-Fi가 함께 나빠지면 테더링이 1순위가 되어 데이터 요금이 나갈 수 있다.
- 로그 회전을 하지 않는다. 5분에 한 줄씩 쌓여 1년이면 약 13MB가 된다.
