macos-net-autoorder

유선이 나빠지면 다른 회선으로 넘어간다

macOS는 케이블이 꽂혀 있는 한 패킷이 새고 느려진 유선을 계속 쓴다. macos-net-autoorder는 5분마다 모든 회선에 ping을 보내 손실률과 지연이 나은 회선을 서비스 순서 맨 위로 올린다.

회선 상태를 바꾼 뒤 다음 주기를 실행해 보자. 스크립트와 같은 규칙으로 순서를 다시 매긴다.

    아직 실행하지 않았다.

    macOS가 넘어가지 않는 이유

    macOS는 링크가 끊기거나, IP를 못 받거나, 라우터가 ARP에 응답하지 않을 때만 서비스 순위를 내린다. 손실률과 지연은 순위에 들어가지 않는다. 그래서 케이블이 꽂혀 있으면 Wi-Fi가 멀쩡해도 나빠진 유선으로 계속 통신한다.

    순서를 정하는 규칙

    • IPv4 주소가 있는 모든 서비스에서 동시에 1.1.1.1로 ping 30회를 보낸다. 각 ping은 해당 인터페이스에 고정해 보낸다.
    • 손실률이 5%p 이상 낮은 서비스를 앞세운다. 손실률 차이가 그보다 작으면 RTT가 상대의 70% 미만인 서비스만 앞세운다. 평소 유선과 Wi-Fi의 몇 ms 차이로는 순서가 바뀌지 않는다.
    • 1순위의 손실률이 20% 미만이고 30초 동안 송수신 합계가 100KB/s를 넘으면 그 주기는 순서를 유지한다. 순서가 바뀌면 SSH, 화상회의 같은 기존 연결이 끊기기 때문이다.
    • 1순위의 손실률이 20% 이상이면 사용 중이어도 순서를 바꾼다. 나빠진 회선도 재전송 때문에 트래픽은 계속 흐른다.

    설치

    git clone git@github.com:wonjiko/macos-net-autoorder.git
cd macos-net-autoorder
sudo ./install.sh

    서비스 순서를 바꾸려면 관리자 권한이 필요해서 root LaunchDaemon으로 돈다. 동작은 로그로 확인한다.

    tail -f /var/log/net-autoorder.log

    제거는 sudo ./install.sh uninstall이다.

    한계

    • 측정 대상이 1.1.1.1 하나다. 이 주소를 막는 네트워크에서는 순서를 그대로 유지한다.
    • 휴대폰 테더링도 후보에 들어간다. 유선과 Wi-Fi가 함께 나빠지면 테더링이 1순위가 되어 데이터 요금이 나갈 수 있다.
    • 손실률과 지연만 비교한다. 둘이 비슷하면 대역폭이 더 큰 회선이 있어도 현재 순서를 유지한다.
